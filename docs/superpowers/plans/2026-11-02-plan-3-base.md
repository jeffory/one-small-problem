# One Small Problem, Plan 3: The Base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You fight from the wreck to the base crater and down a carved switchback to a hangar door. Pressing E there takes you into a generated alien base (lift, hangar with a parked saucer, specimen lab, glowing reactor, alien greenhouse) under near-normal gravity, amber and teal light pools and murky fog, and you fight through it to the comms room door. Death restarts the current area. Five golf balls are hidden on each Moon. It all still ships as one packed HTML file well under 131,072 bytes. The plan opens with Plan 2's carry-over and ends by pinning the golden checksums.

**Architecture:**
- **Generation:** `src/gen/world.js` adds `generateWorld(seed)`, the single entry point. It runs the surface, the crater carve, the fight plan and the base. New pure modules:
  - `crater.js`: the switchback and the hangar door
  - `base.js`: graph → rooms → tile grid
  - `baseplan.js`: lamps and base pacing

  The determinism rules are unchanged, and `src/gen` has no import cycles.
- **Simulation:** the fight runs on a *level* (`src/game/areas.js`): a ground function, a ceiling function, a bound, gravity, a nav grid and a plan.
  - There are four areas on two levels: surface and crater on the surface level, base and comms on the base level.
  - The player, bolts, sight lines and aliens learn about ceilings and tile walls.
  - The sim stays pure and seeded.
- **Look:**
  - `src/game/baseMesh.js` builds the base as two merged meshes.
  - `src/game/baseScene.js` is render mode 1, with fog and the generated lamps.
  - Each frame `fightView` picks 16 lights from the lamps and the plasma lights, and fades lamps in.
  - `main.js` swaps scenes at the hangar door.

This is plan 3 of 4. **Plan 4 (show)** covers audio, radio, the opening and lander break-up, the title screen and attract bot, the comms-room final stand (hold music, waves from the spawn doors, Houston), the end screen, Esc pause and settings.

**Not in this plan:**
- Anything that plays in the comms room: hold music, waves, Houston, the door closing behind you. The room is built and is its own area, with its spawn doors recorded for Plan 4.
- Audio, radio and music. They hook into `F.events`, which gains `area` and `golf` here.
- The end screen's golf tally. `F.found` and `F.golf` are ready for it.
- Retuning Plan 2's tables. The user's hands-on check is still pending.

**Tech Stack:**

- `node:test` for unit tests.

## Global Constraints

**Carried from Plans 1–2 unchanged**
- **Output:** one self-contained `.html` file of at most **131,072 bytes** on disk. The build fails over the cap.
- **Runs from:** `https://` and `file://`. It makes no network requests except the universal decoder's re-fetch of its own file.
- **Packing:** `universalDecoder: true, compactHtml: false`. Keep the `<!doctype html>`.
- **Graphics:** WebGL2 only, with a half-float colour target via `EXT_color_buffer_float` and an RGBA8 fallback.
- **Code:** plain JavaScript with no runtime dependencies. Every file under `src/`, `tools/` and `build.mjs` is 7-bit ASCII; use `\u` escapes in strings.
- **Determinism in `src/gen/**`:**
  - Allowed: `+ - * /`, bit operations, `Math.imul/sqrt/floor/ceil/round/trunc/min/max/abs`.
  - Never: `Math.sin/cos/tan/asin/acos/atan/atan2/pow/exp/expm1/log*/hypot/cbrt/random`, `**`, `Date` or `.sort(`.
  - The same seed gives byte-identical world data in every browser and in Node.
- **Coordinates:** metres, y up. The player faces −z at yaw 0, and forward is `(−sin yaw, −cos yaw)`. Height-field sample `(i, j)` sits at world `(i − 256, j − 256)`.
- **Alien yaw:** an alien with yaw `a` faces `(sin a, 0, cos a)`. Turning toward a point uses `atan2(px − x, pz − z)`.
- **Simulation is pure:** `src/game/{weapons,bolts,nav,rigs,aliens,fight,models,areas,baseMesh}.js` never touch `document.`, `window.`, `gl.`, `performance.now`, `Date.now` or `Math.random`. All game randomness comes from `makeRng(world.seed + '/sim')`.
- **Sub-steps:** at most 0.05 s each, with a 0.25 s stall cap. One-shot inputs (`use`, `weapon`, `wheel`) apply on the frame's first sub-step only.
- **Per-frame render caps:** 16 point lights, 8 sphere occluders, 512 sprites.
- **Look:** 270 px internal height, the 51-colour palette with 4×4 Bayer dither, 256² textures, sun 1.55, vertical FOV 62°, exposure 1.
- **Names read from outside the bundle** (`window.ospTest`, GLSL uniforms) are never `_`-prefixed.

**New for Plan 3**
- **One way to build a world:** `main.js`, the soak and every test that needs a fight plan use `generateWorld(seed)`. `src/gen` has no import cycles (tested in Task 1).
- **Checksums** cover everything `generateWorld` produces. The golden values are pinned in Task 12, once generation is final.
- **The base level:**
  - It is a 96 × 96 grid of 1 m tiles: 8 × 8 coarse cells of 12 tiles. Tile `(i, j)` sits at world `(i − 48, j − 48)`. **[call]** The grid needs only about 0.1 MB. The nav field is a 96-tile window centred on the player, so it covers the whole base only when the player stands at the grid centre; alerted aliens outside it get no field direction and head straight for the player. (pre-flight F26)
  - Wall tiles have floor 99 and ceiling 0. The outermost ring of tiles is always wall. (pre-flight F8)
  - Every walkable tile has at least 2.6 m of headroom.
  - `ground(x, z)` and `ceil(x, z)` read the nearest tile. Outside the grid, `ground` returns 99 and `ceil` returns 0.
- **Gravity** comes from one table, `GRAVITY = {surface: 3.0, base: 9.0}` in `src/game/areas.js`. Both scenes and the fight read it. **[call]** The scene's `gravity` stays, but the pure fight can't see a GPU scene, so both read the same constant, and a test checks they agree.
- **Areas:**
  - `AREAS = ['surface', 'crater', 'base', 'comms']`. The surface and crater share the surface level; the base and comms share the base level.
  - You only ever advance, never go back.
  - Entering an area snapshots your inventory. Death restarts the current area from its start with that snapshot.
- **Lights:**
  - At most 16 per frame. Lamps take at most `16 − MAX_DYN = 10` slots and dynamic lights fill the rest: `nDyn = min(dynCount, 16 − min(lampCandidates, 16 − MAX_DYN))`. (pre-flight F18)
  - No walkable tile is reached by more than `LIGHT_CAP = 10` lamps, sampled at floor + 1.7 and at floor + 2.4. (pre-flight F28)
  - A lamp's radius is at most the horizontal distance to the nearest non-wall tile it cannot see: a 2D line of sight over the tile grid from the lamp, where wall tiles block. Base mode has no shadows, so light would otherwise pass through walls; walls between spaces are at least 2 tiles thick, so every tile behind one is hidden and bounds the radius. Room lamps hang at floor + `LAMP_DROP = 2.65`, the look test's height. (ruling R16, which replaces pre-flight F16's `LEAK = 1.5` wall-clearance clamp: that left 74% of walkable tiles unlit)
- **Look anti-goals (§2):**
  - The base fog stays below 0.03 linear in every channel.
  - Lamp colours are the look test's.
  - Wall panels emit nothing; glow strips are separate geometry, at most one per room, in about 40% of rooms.
- **Per-frame allocation:** `fillFrame` allocates no `Float32Array` once warm. Aliens draw out to 80 m.
- **Tuning tables:**
  - New: `CRATER`, `CRATER_P`, `CRATER_AT`, `BASE`, `THEME_AT`, `LIGHT`, `BASE_SCALE`, `GRAVITY`, `WAKE`, `ALIENS.fl.top/below`.
  - Plan 2's `WEAPONS`, `ALIENS` combat numbers, `PICKUP`, `CANISTER` and `budgetAt` are unchanged.
  - Tests read these constants, except for structural facts.
- **Size:** expect about 45–60 KB after this plan. Above 80 KB, record a ruling with the cause.

## Review Focus

1. **Dying exactly at an area boundary.** Crossing into the crater and taking a lethal hit in the same step restarts you at the crater top with what you crossed with. A dead body knocked over the rim never changes the area. Tested in Task 8.
2. **Entering the base with bolts, goo, a boom or a lit canister fuse in flight.** Nothing from the surface follows you in, and nothing explodes later. Tested in Task 8.
3. **A seed whose base can't be finished.** Every walkable tile, the comms door, every alien, pickup and golf ball is reachable from the lift for 1,000 seeds. Failed layouts re-roll and give up loudly. Tested in Tasks 4 and 5 and in the soak.
4. **Light popping when the 16-light set changes,** including in a crowded fight. No lamp that reaches you is dropped, and lamps that join fade in from dark. Tested in Task 10.
5. **Getting stuck on tile corners or under low ceilings.** You slide past corners and door jambs and keep 0.37 m from walls. A blast that throws you up stops your head at the ceiling. A doorway lintel never lets your head through or pins you. Tested in Task 6.

### Task 2: Crater switchback and the hangar door (generation)

**Files:**
- Create: `src/gen/crater.js`, `tests/crater.test.mjs`
- Modify: `src/gen/world.js`, `src/gen/checksum.js`, `src/game/props.js`, `src/game/surfaceScene.js`, `src/gfx/materials.js`, `tests/seeds.soak.mjs`

**Interfaces:**
- **Consumes:**
  - `sampleBilinear`, `stampOccluders`, `distToPolyline`, `surfaceAccept`, `N`, `HALF`, `MAP_MARGIN` and `MAX_STEP` from `surface.js`
  - `passable` and `makeRng`
- **Produces, from `crater.js`:**
  - The table:
    ```
    CRATER = { legs: [[1.05, 0], [.92, 1], [.76, -1], [.60, 1], [.42, 0]], w: [.25, .31], half: 3, blend: 4,
               door: .30, use: 1.8, pad: { at: .36, r: 12, blend: 4 }, bunker: { w: 7, d: 6, h: 4.5 } }
    ```
  - `carveCrater(world) => Crater`, where:
    ```
    Crater = { path: [[x, z] × 5], ys: [y × 5], top: {x, z, dx, dz}, door: {x, y, z, dx, dz}, use: {x, z},
               bunker: {x, z, ux, uz, w, d, h, y} }
    ```
  - `carveCrater` mutates `world.h`, `world.occ` and `world.rocks`.
- **The carve, using only arithmetic and `sqrt`:**
  1. **Frame:** `C = world.base` and `R = C.R`. `u` is the unit vector from `C` toward `world.rim`, and `t = (−u.z, u.x)`. `rng = makeRng(seed + '/crater/' + attempt)`. Draw `side = rng.next() < .5 ? 1 : −1`, then `w = R·rng.range(.25, .31)`.
  2. **Waypoints:** `P_k = C + u·(f_k·R) + t·(side·s_k·w)` for each `[f_k, s_k]` in `CRATER.legs`. `P_0` is the route's last point itself (copied), not recomputed.
  3. **Heights:** `ys` runs linearly in arc length from `y0 = sampleBilinear(h, P_0)` to `yE = sampleBilinear(h, P_4)`, both read before any carving.
  4. **Pad:** around `Q = C + u·pad.at·R`, set `h += (yE − h)·(1 − smoothstep(pad.r, pad.r + pad.blend, |p − Q|))`.
  5. **Carve,** after the pad, so the path's own heights win on its strip: for every sample within `half + blend` of the path, find the nearest polyline point (arc `s`, distance `d`), and set `h += (y(s) − h)·(1 − smoothstep(half, half + blend, d))`. (pre-flight F1: with the pad cut after the path, the pad flattened the last ~8 m of leg 3 into a 0.5–0.66 m step.)

  7. **Door and bunker:** the door is `D = C + u·door·R`, with `door = {x, y: yE, z, dx: u.x, dz: u.z}`. The use spot is `D + u·CRATER.use`.   8. **Top:** `top = {x, z}` of `P_0`, with `(dx, dz)` the unit vector from `P_0` to `P_1`.

export function tileLevel(rows, { ceil = 3, wall = 99 } = {}) {
  const n = Math.max(rows.length, ...rows.map(r => r.length)), floor = new Float32Array(n * n).fill(wall), top = new Float32Array(n * n);
  rows.forEach((r, j) => [...r].forEach((c, i) => { if (c !== '#') { floor[j * n + i] = c === 'c' ? 1.1 : 0; top[j * n + i] = c === 'l' ? 2.6 : ceil; } }));
  const at = (a, x, z, out) => { const i = Math.round(x), j = Math.round(z); return i < 0 || j < 0 || i >= n || j >= n ? out : a[j * n + i]; };
  const solid = (i, j) => i < 0 || j < 0 || i >= n || j >= n || floor[j * n + i] >= wall;
  return { n, ground: (x, z) => at(floor, x, z, wall), ceil: (x, z) => at(top, x, z, 0),
    gap(x, z) { let g = Infinity; for (let j = -1; j <= n; j++) for (let i = -1; i <= n; i++) if (solid(i, j)) g = Math.min(g, Math.hypot(Math.max(0, Math.abs(x - i) - .5), Math.max(0, Math.abs(z - j) - .5))); return g; } };
